# Contributing to AgilFrame

[Русский](CONTRIBUTING.md) · **English**

Make changes in the repository that owns the component. Start from the latest `main` and name the branch for the work, such as `feature/room-invites`, `fix/token-expiry`, or `docs/deployment`. Pull request authors must review the entire diff and are responsible for all changes, including AI-assisted code. [Issue and pull request guidelines](https://github.com/GillHD/agilframe-core/blob/main/CONTRIBUTING.en.md)

Write commit subjects in the imperative mood, for example `Update the Core submodule`. For substantial changes, use the commit body to explain what changed, why, and how you verified it. In the pull request, summarize the change and list the checks you ran.

For changes to this repository, check links, submodule revisions, and clone commands. When updating a component, include a link to its pull request, the old and new commit SHAs, and the compatibility checks you ran. [Update component versions](docs/repositories.en.md#update-component-versions)
